# Red-team of proposal v0 (2026-10-17)

Two independent reviews of `docs/PROBLEM.md` and `docs/ARCHITECTURE.md` v0:
- **A**: a Claude subagent briefed to try to kill the proposal. It ran its own probes against data.gov.lt, e-tar and web search.
- **B**: a second, open-weights model from a different model family, which raised 17 objections (7 high).

Claude's verdict on each finding is in **[brackets]**.

## A: subagent findings (ranked)

1. **MAJOR: the freeze is proven for one act, not the whole dataset.** The reviewer couldn't re-run dataset-wide queries because the API went 504, then 502.
   **[Partly resolved]** Before the outage, Claude's count queries returned 0 rows with `suv_duom_atnaujinimas >= 2025-06-01` and 1,543 rows after 2025-05-03, across all 333k rows. The dataset changelog records a one-time load on 2025-06-13. The remaining gap is rows with a null timestamp. Phase 1 step 1 is the full histogram. **Resolved later on 2026-10-17:** a full download of all 333,292 rows shows the newest timestamp is from 2025-05, with 10,218 NULLs. ANK's current e-tar version (2026-10-01) is missing from the dump. See `staleness_2026-10-17.txt`.
2. **MAJOR: the source API is a single point of failure.** It timed out, then returned 504 and 502 within an hour.
   **[Accepted]** Do the initial load once, resumable, and keep our own snapshot. Treat outages of a day or more as normal.
3. **MAJOR: gap-filling from e-tar is the product, and it's the legally weakest part.** The database right is separate from copyright (see Norway, rettspraksis.no), and no terms of use were found.
   **[Accepted]** Ask the Chancellery in writing, or get the free data contract, before fetching e-tar at scale. Until then, fetch only a short, hand-picked list.
4. **MAJOR: the problem is real but smaller than claimed.** The popular article (DK 52) was answered correctly via lrvalstybe. The niche law gave a stale answer, and CK 6.188 got no text at all. "Closed to AI" is overstated: infolex lets Googlebot and Bingbot in; lrvalstybe blocks only training bots; user-fetchers ignore robots.txt.
   **[Accepted]** Retarget to the long tail plus "which version applies today", and rewrite PROBLEM §1–2C.
5. **MAJOR: "survives neglect" fails on GitHub Actions.** Schedules in public repos switch off after 60 days without activity. Runners have about 14 GB of disk and a 6-hour limit. D1 is capped at 500 MB free and 10 GB paid. A Worker counts every request, even cache hits.
   **[Accepted]** v1 is small enough for a free static host. The nightly data commit doubles as the keep-alive, and an external heartbeat alerts when data goes stale.
6. **MAJOR: personal data.** Individual acts name people: citizenship, pardons, awards, appointments.
   **[Accepted, important]** v1 uses an allowlist of normative act types and issuers, excludes individual acts, and publishes a takedown address.
7. **MAJOR: detecting pending changes from titles is unreliable.** It misses omnibus laws, "nauja redakcija" (new wording) and repeal acts, Constitutional Court rulings, and postponed entry into force. A missing box reads as "nothing pending".
   **[Accepted]** Never imply that nothing is pending. Wording: "detected N; detection incomplete; check e-tar". Look for a relations field in the data first.
8. **MAJOR: the crawl-budget trap.**
   **[Accepted]** v1 covers 20–40 codes and laws, roughly 10–20k article pages. Government resolutions and orders wait for v2.
9. **MINOR: the showcase.** The Electricity Law is a narrow example to lead with; few people ask about it.
   **[Accepted]** Use DK and CK as examples.
10. **MINOR: liability and licence.** Consolidated texts aren't legally "official" (Teisėkūros pagrindų įstatymas, Art. 2(5)). The CC BY 4.0 licence still has to be confirmed.
    **[Accepted]** The landscape scout confirmed CC BY 4.0 on the dataset page. Docs now say "consolidation prepared by the Chancellery", not "official consolidation".
11. **MINOR: strategy.** temidy could out-execute us. The only moats are openness and per-article URLs.
    **[Accepted]** The report to the Chancellery is deliverable #1.
12. **MINOR: the 21¹ → "211" heuristic** fails where 21¹ and 211 both exist, and on CK "6.188¹".
    **[Accepted]** For codes, take the e-tar `<sup>` markup as the authority, with golden tests.

**Cheapest validation the reviewer proposed:**
- **Week 0:** write to the Chancellery.
- **Weeks 1–3:** a 5-code static site with Search Console and Bing set up.
- **Weeks 4–12:** go/no-go on indexing, impressions and Copilot citations.

**Reviewer's verdict:** build smaller.

## B: second-model findings (summary)

The high-severity objections were:
- the e-tar legal basis;
- the unknown size of the gap;
- the parser silently publishing wrong text, so the article TOC must be validated for every act;
- pending-changes detection being fragile;
- a cost model missing request fees;
- GitHub Actions limits;
- a licence review.

The medium-severity objections were:
- SEO needs a distribution plan;
- an open MCP invites abuse;
- MCP/OpenAPI are scope creep for v1;
- FTS5 recall in Lithuanian needs measuring;
- diff state belongs in a DB, not R2;
- we need a status page and an outdated-data banner;
- the handover runbook.

The low-severity objections were:
- make HF/GitHub releases the primary dump;
- annex extraction is risky;
- add an alias table and log misses.

**[Accepted, with one rejection]** Requiring API keys contradicts the no-registration goal. We use edge rate limits plus bulk dumps instead. Both reviewers independently converged on: smaller v1, no e-tar dependency without permission, honest staleness signalling, and validating every parse.
